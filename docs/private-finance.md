# إعداد الفوترة الخاصة

## الحالة الحالية

القسم متاح في الشيفرة للنسخة الخاصة فقط: عملاء محليون، مزامنة عميل، عروض أسعار بتصميم سبق، تحويل إلى مسودة فاتورة واحدة، إعداد مفتاح وافق والتحقق من المنشأة، ومسار مزامنة الفاتورة القياسية. لا يوجد إصدار حكومي تجريبي ضمن الاختبارات، ولا بيانات عملاء حقيقية في عينات الاختبار.

لم يُعتمد بعد مسار الطباعة الضريبية النهائية: مرجع وافق العام لا يوضح في مخطط الاسترجاع حقول النتيجة النهائية وQR/XML المطلوبة. الحالة غير المعروفة تبقى بحاجة إلى مصالحة، ويُحجب إخراج الفاتورة النهائية. الفاتورة المبسطة B2C غير مفعلة. لا تعتبر هذه النسخة حلًا مكتملًا للمرحلة الثانية قبل حسم هذه العقود واختبارها في بيئة المزود المناسبة.

تحقق حي للقراءة فقط بتاريخ 14 نوفمبر 2026: نجحت مصادقة المنشأة. أظهرت استجابة فاتورة موجودة بحالة محاسبية `SENT` حقول الفاتورة العادية دون حقول QR أو XML أو نتيجة الهيئة. لم ينشئ هذا الفحص أي عميل أو فاتورة ولم يرسل بلاغًا ضريبيًا. هذه ملاحظة على الاستجابة المفحوصة، وليست إثباتًا لغياب أي إمكانية أخرى لدى وافق.

رُوجع أيضًا دليل النظام السابق المقدم من المالك؛ نتائج المراجعة والفجوة المطلوب حسمها مع المزود موثقة في [مراجعة دليل الفوترة](billing-guide-review.md). فحص مسار الحالة القديم على فاتورة موجودة أعاد HTTP 404؛ لم يُنقل إلى التطبيق الجديد.

طلب المالك تجهيز الاستفسار للدعم؛ [الرسالة الجاهزة لوافق](wafeq-support-request.md) محفوظة ولم تُرسل.

## مكان المفتاح

بعد تشغيل هذه النسخة الخاصة وإعطاء الحساب صلاحية الفوترة:

1. افتح **النظام المالي ← إعدادات وافق**، أو المسار `/finance?tab=settings` بعد تسجيل الدخول.
2. أدخل مفتاح **Wafeq Accounting API** في حقل «مفتاح واجهة وافق» واضغط «حفظ المفتاح».
3. تحقق من اسم المنشأة الظاهر، ثم استخدم «اختبار الاتصال بوافق». الاختبار يقرأ المنشأة ولا ينشئ فواتير.
4. أكمل بيانات البائع ومعرفات حساب الإيراد ونسب الضريبة في وافق قبل تجهيز عروض الأسعار. بيانات البائع تُنسخ إلى العرض عند إنشائه.
5. أضف بيانات الحساب البنكي الاختيارية لعرضها في القالب. تُحفظ مشفرة مع البائع وتثبت في العرض والفاتورة؛ تغيير الإعدادات لا يستبدل بيانات المستندات القديمة. التحقق من IBAN يتحقق من الصيغة ورقم التحقق، وليس من ملكية الحساب.

لا تُرسل المفتاح في المحادثة أو البريد ولا تضعه في متغيرات `VITE_*`. المفتاح لا يظهر مرة أخرى بعد الحفظ. تغيير مفتاح التشفير `HR_DATA_KEY` دون ترحيل الأسرار سيمنع قراءة البيانات السابقة.

## متغيرات التشغيل

- احتفظ بإعدادات النسخة الخاصة الواردة في [دليل التشغيل الخاص](private-local.md).
- أضف `HR_FINANCE_EMPLOYEE_ID` بمعرّف الحساب الممنوح فعليًا. لا يكفي الاسم أو الدور، ولا تضف هوية الموظف إلى ملفات Git.
- التشغيل المستضاف يحتاج `HR_DATA_KEY` ثابتًا وHTTPS وبوابة الدخول الحالية.
- غياب `HR_FINANCE_EMPLOYEE_ID` يعطل الوصول للقسم بالكامل. المعاينة العامة ترفضه حتى لو ضُبط المتغير.

بوابة الدخول الحالية بكلمة مرور مشتركة لا تثبت هوية كل شخص على حدة؛ من يعرفها يستطيع اختيار حساب ممنوح. تبقى قيود [قرار 006](decisions/006-private-hosted-password.md) سارية.

## الترحيل والتراجع

الترحيل `009_finance.sql` يضيف جداول مالية مستقلة في SQLite وPostgreSQL دون تعديل سجلات الموارد البشرية. يطبق داخل معاملة، ويستخدم قيودًا لمنع تحويل العرض إلى فاتورتين أو تكرار أرقام المستندات. التهيئة الخاصة لا تضيف حسابات أو بيانات وهمية.

قبل نشره على قاعدة فعلية، احتفظ بنسخة احتياطية قابلة للاستعادة ومفتاح التشفير خارج النسخة. افحص الفرع والإصدار المنشورين للخدمة الخاصة قبل الدمج. الاختبارات المحلية ليست إثباتًا للنشر.

لإيقاف الميزة، أزل متغير منح الصلاحية وأعد تشغيل الخدمة، أو ارجع إلى الإصدار السابق. احتفظ بجداول الفواتير ومفاتيح العمليات والأسرار؛ لا تحذفها لإعادة المحاولة. التراجع عن الشيفرة لا يلغي فاتورة سبق إرسالها لوافق، ولا يجوز تكرار إنشائها بمفتاح جديد بدل المصالحة.

## التحقق المحلي

```bash
npm run typecheck
npm test
npm run build
npm run test:e2e
npm run test:finance
```

لتحقق PostgreSQL، اضبط `HR_TEST_DATABASE_URL` لقاعدة اختبار محلية منفصلة. ينشئ اختبار المالية مخططًا مؤقتًا ويحذفه عند الانتهاء. لا تستخدم رابط قاعدة الإنتاج في الاختبارات.

اختبارات المتصفح المالي تستخدم خادمًا خاصًا ببيانات اصطناعية ومزود وافق وهمي على `127.0.0.1:4319`؛ لا تقرأ ملف `.env` ولا تتصل بوافق. اختبار قبول وهمي بلا QR يجب أن يبقي الطباعة النهائية محجوبة. لا تدخل مفتاحًا حقيقيًا في خادم الاختبارات.

## سجل التحقق في 14 نوفمبر 2026

- `npm run build`: نجح، بما يشمل TypeScript. يوجد تحذير Vite عن حزمة تتجاوز 500 كيلوبايت، دون فشل بناء.
- `HR_TEST_DATABASE_URL=… npm test`: نجحت الاختبارات الـ125 دون تخطٍّ، على SQLite وPostgreSQL محلي معزول. يشمل ذلك تعارض تحديث الإعدادات، رفض المزامنة غير المدعومة قبل اتصال المزود، وحفظ بيانات البنك في لقطات مشفرة وثابتة.
- `npm run format:check` و`git diff --check`: نجحا.
- اختبارات واجهة HR السابقة: نجح 24 سيناريو في الدورة الأولى؛ كُشف تسرب تنسيق من الوحدة المالية إلى أزرار الصفحة الرئيسية، وأُصلح بعزل التنسيق. أعيد السيناريوان المتأثران على Chromium وWebKit ونجحا.
- `npm run test:finance`: نجح مسار العمل المالي على Chromium وWebKit (2/2)، بما يشمل فحص الوصول وتصميم عرض 320 بكسل. راجعت لقطات إعدادات المفتاح وعرض السعر؛ لا يظهر QR في عرض السعر، وتبقى الطباعة النهائية محجوبة عند غياب المخرج الرسمي.
- فُحص PDF اصطناعي بثلاثة بنود عربية طويلة وبيانات بنك وملاحظات: صفحة A4 واحدة واضحة دون تذييل منفصل. أُصلح تعارض إخفاء نافذة المعاينة في الطباعة، وأضيف فحص يمنع رجوع ملف PDF الفارغ. هذا PDF لعرض سعر تجريبي، وليس فاتورة ضريبية معتمدة أو ملف PDF/A-3.
- المفتاح الحقيقي اختُبر للقراءة فقط وحُفظ مشفرًا خارج ملفات Git. فحص ملفات المستودع لم يجد قيمة المفتاح. لم تُجرَ عمليات إنشاء أو إبلاغ فعلية في وافق.

الملفات الأساسية: `server/finance/routes.ts`، `server/integrations/wafeq.ts`، `src/finance/`، `shared/finance.ts`، والترحيل `009_finance.sql` لكلتا القاعدتين. أضيفت اختبارات مالية ومصادقة ومزامنة واختبارات متصفح مستقلة. لم تُنشر هذه الدفعة على خدمة الإنتاج الخاصة.
