# تشغيل سبق HR ببياناتك الحقيقية على جهازك فقط

هذا الوضع يشغّل النظام على جهازك الشخصي ببيانات الموظفين الفعلية وصورهم، بلا أي بيانات وهمية. لا يرفع شيئًا إلى الإنترنت، ولا يمس المعاينة العامة على Railway ولا قاعدة Neon. القرار والتفاصيل التقنية في [قرار 005](decisions/005-private-local-mode.md).

## قبل أن تبدأ

- Node.js 24 أو أحدث (`node -v`).
- ملف الموظفين بصيغة xlsx، بنفس عناوين أعمدة ملف التصدير (اسم الموظف، البريد الإلكتروني، تاريخ التعيين، على رأس العمل، الصورة…).
- احفظ الملف خارج مجلد المشروع، مثلًا في `~/Documents/hr-private/`. لا تضعه داخل المستودع.

## الخطوات

### 1. جلب النسخة

```bash
git clone https://github.com/sabq4org/HR.git   # أو git pull إن كان المستودع عندك
cd HR
git checkout claude/project-thread-e4jmmy
npm ci
```

### 2. تجربة الاستيراد دون حفظ

```bash
npm run private:import -- ~/Documents/hr-private/employees-with-photos.xlsx --dry-run --include-incomplete
```

تطبع الأداة أرقامًا فقط: عدد الصفوف، وعدد من سيُستورد، وعدد الصور، وأرقام الصفوف المتخطاة وسببها، والأعمدة المقروءة والمتجاهلة. لا تطبع أي اسم أو رقم هوية.

- بدون `--include-incomplete` يُتخطى كل من ليس له بريد أو تاريخ تعيين. في ملف التصدير الحالي هذا يعني 27 موظفًا فقط.
- مع `--include-incomplete` يُستورد الجميع (75 موظفًا و15 صورة)، ويوضع لمن ينقصه شيء قيمة مؤقتة صريحة:
  - البريد: `sbq-00NN@pending.invalid`، وهو عنوان لا يعمل.
  - تاريخ التعيين: تاريخ يوم الاستيراد.
  - المسمى والقسم والموقع: «غير محدد».

### 3. الاستيراد الفعلي

```bash
npm run private:import -- ~/Documents/hr-private/employees-with-photos.xlsx --include-incomplete
```

- تُنشأ القاعدة في `.data/hr-private.sqlite` ومفتاح التشفير في `.data/hr-data.key`.
- الصور والبيانات الحساسة مشفرة داخل القاعدة.
- إعادة التشغيل لا تكرر أحدًا: من له بريد يُعرف ببريده، ومن ليس له بريد يُعرف باسمه.
- الأرقام الوظيفية تُولّد بصيغة `SBQ-0001` وما بعدها.

### 4. منح الأدوار

لا يستطيع أحد الدخول قبل أن تمنحه دورًا. ابدأ بنفسك أو بمسؤول الموارد البشرية:

```bash
npm run private:access -- grant hr.person@sabq.org hr
npm run private:access -- grant SBQ-0007 manager
npm run private:access -- manager SBQ-0012 SBQ-0007   # SBQ-0007 مديرًا مباشرًا لـ SBQ-0012
npm run private:access -- list                        # كل الموظفين وأدوارهم
npm run private:access -- incomplete                  # من بقيت عليه قيم مؤقتة
```

- الأدوار المتاحة: `hr`, `manager`, `finance`, `approver`, `auditor`, `employee`.
- يُعرَّف الموظف ببريده أو رقمه الوظيفي.
- كل منح وتعيين يُسجّل في سجل التدقيق غير القابل للتعديل.
- لا يُمنح دور لموظف منتهية خدمته أو موقوف.

### 5. التشغيل

```bash
npm run private
```

افتح <http://127.0.0.1:4317>. ستظهر شارة «بيانات خاصة · هذا الجهاز فقط»، وقائمة الدخول تعرض فقط من منحتهم دورًا غير «موظف».

## من يرى الصور

تظهر الصورة في فريق العمل وملف الموظف لثلاثة فقط:

- الموظف نفسه.
- الموارد البشرية.
- المدير المباشر.

المالية والمعتمد والمراجع لا يرونها. هذا افتراض محافظ قابل للتوسيع بقرارك.

## النسخ الاحتياطي

انسخ الملفين معًا، فالقاعدة بلا المفتاح لا تُقرأ:

- `.data/hr-private.sqlite`
- `.data/hr-data.key`

احفظ النسخة في مكان مشفر، مثل قرص بـ FileVault. لا ترفعهما إلى Git أو أي خدمة سحابية عامة.

## حدود هذا الوضع الآن

- **الإجازات:** لا تُنشأ طلبات إجازة، فلا توجد سياسة إجازة حقيقية معتمدة بعد، وتظهر رسالة توقف واضحة.
- **الرواتب:** لا توجد رواتب في القاعدة. الرواتب والبدلات في الملف الثاني لم تُستورد عمدًا، فلا تُعد مسيرات بعد.
- **المستندات:** الرفع من الواجهة محكوم بحد المعاينة (30 مستندًا و6 ميجابايت لكل المساحة)، والصور المستوردة تُحتسب منه. رفع هذا الحد قرار لاحق.
- **الأعمدة المتجاهلة عمدًا:**
  - نوع الموظف، الحساب نشط، الجوال الاحتياطي.
  - التأمين الطبي.
  - تفاصيل الحساب البنكي غير الآيبان.
  - أيام الإجازة.
  - النبذة.
- **الدخول:** لا يوجد دخول بكلمة مرور. الجهاز نفسه هو الحماية، والخادم يستمع على `127.0.0.1` فقط. الدخول المؤسسي (SSO) هو المرحلة التالية مع Neon.
