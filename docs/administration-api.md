# عقد واجهات الشؤون الإدارية

كل المسارات أدناه مسبوقة `/api/admin`. الجلسة والصلاحية في الخادم؛ لا يقبل actor من الجسم. كل mutation يحتاج `Idempotency-Key` فريدًا، إعادة نفس العملية تعيد النتيجة السابقة، واستخدام المفتاح بمحتوى مختلف 409. `version` إلزامي عند تعديل سجل موجود. الأخطاء `{error:{code,message}}`. التواريخ ISO، الأوقات بتوقيت الرياض، المال في حقول النماذج بالريال وبحد منزلتين؛ خطوط المسير بوحدات هللة صحيحة. القواعد اصطناعية ولا تثبت حقوقًا قانونية.

Shared definitions live in `shared/administration.ts`, fields/catalog in `shared/catalog.ts`. The UI imports shared descriptions while the server enforces the same allowed field names/types and workflow. No arbitrary JSON settings editor in normal employee flows.

Role policy: employee own data; manager direct team with personal/financial/medical fields omitted; HR employment administration; finance financial records only; approver decisions with needed details; auditor redacted read-only. No self approval by creator or subject. `stepsByInitiator` explicitly defines synthetic routes where a specialist prepares a recommendation and an independent role decides: HR-prepared employment/reward/separation/discipline goes to approver; manager's own special leave goes to HR; manager-prepared overtime goes to HR then approver. Persist selected steps on creation. Never infer further step skipping. Show an actionable explanation when no independent actor is available in this preview.

Core integration: `registerAdministration(app,{db,requireActor})` called before API 404. `db` uses async read/execute/transaction methods and SQL `?` placeholders for SQLite/Postgres. Each transaction must use its passed tx. No nested transactions. Payroll gets separate `registerPayroll(app,{db,requireActor})` called from root routes.

## Excel employee import

HR-only `GET /imports/employees/template` downloads the two-sheet XLSX template. `POST /imports/employees/preview` accepts `{filename,contentBase64}` and returns a validated preview; `POST /imports/employees/commit` accepts the preview rows and an idempotency key, validates again and creates the whole batch atomically. Limits: 2 MiB upload, 100 rows, 200 employees per workspace. Formula cells and unsafe workbook packages are rejected.
