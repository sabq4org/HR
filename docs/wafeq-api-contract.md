# Wafeq Public API contract used by the finance adapter

This integration targets the Wafeq Public API for the private organization API key workflow. It creates standard accounting invoices in Wafeq and uses their tax authority reporting action. It does not call the standalone ZATCA API, which does not create Wafeq accounting records.

## Verified routes and payload

All requests use the fixed origin `https://api.wafeq.com/v1/`, `Authorization: Api-Key …`, JSON requests, and redirects are rejected.

| Operation                           | Route                                        | Contract notes                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ----------------------------------- | -------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Read organization                   | `GET /organization/`                         | Returns a string `id` and bilingual `name` object (`en`, optionally `ar`) that identify the API-key tenant. The adapter normalizes the Arabic name, falling back to English.                                                                                                                                                                                                                                                                         |
| Create contact                      | `POST /contacts/`                            | The v1 contact schema defines `name` as a scalar string. It is passed through from the customer's saved `name`; optional `nameEnglish` is not merged or guessed into the scalar. Other mapped fields are `email`, `tax_registration_number`, `address`, `city`, `postal_code`, `country`, `is_customer`, and `external_id`; documented optional address detail and phone are passed when present.                                                    |
| Find contact by source key          | `GET /contacts/?external_id=…&page_size=100` | Exact returned `external_id` match is required; pages are requested through the fixed API origin, without following returned `next` URLs. Invalid result shapes stop the operation.                                                                                                                                                                                                                                                                  |
| Create standard invoice             | `POST /invoices/`                            | Uses Wafeq v1 `contact`, `currency`, `invoice_date`, `invoice_due_date`, `invoice_number`, `reference`, optional `purchase_order`, `external_id`, `tax_amount_type`, and line item `description`, `account`, `quantity`, `unit_amount`, `tax_rate`. Quantity and source unit price are sent from their validated domain strings; the rounded subtotal is not divided back by a fractional quantity. Simplified invoices are rejected by the adapter. |
| Find standard invoice by source key | `GET /invoices/?external_id=…&page_size=100` | Exact returned `external_id` match is required; pages are requested through the fixed API origin, without following returned `next` URLs. Invalid result shapes stop the operation.                                                                                                                                                                                                                                                                  |
| Read invoice                        | `GET /invoices/{id}/`                        | Wafeq invoice `status` (`DRAFT`, `SENT`, `FINALIZED`) is an accounting lifecycle status, not proof of a tax authority verdict.                                                                                                                                                                                                                                                                                                                       |
| Report invoice                      | `POST /invoices/{id}/tax-authority/report/`  | This is the documented reporting action for a Wafeq accounting invoice. Do not recreate the invoice through `/zatca/`.                                                                                                                                                                                                                                                                                                                               |
| Download PDF                        | `GET /invoices/{id}/download/`               | Documented response is `application/pdf`; no caller-provided URL is followed.                                                                                                                                                                                                                                                                                                                                                                        |

Every create/report POST passes the caller-provided `X-Wafeq-Idempotency-Key` after checking it is UUID-shaped. The client does not generate durable source IDs or idempotency keys.

Wafeq's create schema requires `invoice_number`; the client sends the stable finance invoice number supplied by the caller. The finance domain reserves that number at conversion and separately tracks legal document status, so a draft status does not change the reserved identifier.

The HR model currently stores `taxReason` as free text. Wafeq's line item schema describes `tax_exemption_reason` as a reason code offered by the selected tax rate, except for the KSA out-of-scope rate where a written reason is used. This adapter has no approved mapping from local free text to a Wafeq code or a confirmed out-of-scope tax-rate selection. Therefore any invoice with a zero-rated line is rejected before a provider request. The `zeroTaxRateId` mapping remains stored for future use once an approved reason-code mapping exists.

## Reporting and artifacts

The published report operation schema says the response is `{status: string, reported_ts, metadata: {errors, warnings}}`. Its description explicitly defines `PENDING` as accepted while the tax authority verdict is outstanding; it says to retrieve the invoice for the final status. A concurrent report/retry can return HTTP 409 with code `report_in_progress`, so the client rereads the invoice. The public schema does not enumerate final status strings, and the invoice retrieval schema documents no tax authority field. The adapter therefore preserves a returned raw tax authority status for the caller but only maps the documented `PENDING` value; other values remain `unknown`. Wafeq accounting status is never mapped to clearance.

The documented v1 invoice/report schemas do not expose a QR code or XML artifact field, and the download operation documents PDF only. `qrCode` is always `null` in this adapter. A caller must not mark an invoice cleared or publish a final branded tax invoice on the basis of an HTTP 200 response, Wafeq accounting status, guessed field names, or this PDF. No XML endpoint or embedded XML extraction is asserted by this contract.

The standalone ZATCA endpoints are intentionally not used: Wafeq says they create compliance documents outside the Wafeq accounting application. The intended route for an invoice that must exist in Wafeq accounting is create through `/invoices/`, then report that invoice through the action above.

## Error and request handling

Errors expose only a short provider code and HTTP status; response details, credentials, request URLs, and bodies are not included in error messages. Requests time out after 12 seconds. JSON responses are capped at 2 MiB and PDF responses at 12 MiB. The PDF is fetched only from the fixed invoice route and requires `application/pdf`. The adapter performs no live calls as part of its tests and reads no environment variables.
