# سبق — مساحة الفريق

تأسيس لنظام شؤون الموظفين: واجهة عربية RTL وAPI وقاعدة بيانات علائقية، مع تطوير محلي ومعاينة مستضافة معزولة ببيانات اصطناعية فقط. ليس نظامًا معتمدًا للإنتاج أو للرواتب.

## التشغيل

المطلوب Node.js 24.13 أو أحدث وnpm. لا حسابات سحابية أو مفاتيح مطلوبة.

```sh
npm ci
npm run dev
```

افتح http://127.0.0.1:4317 . تُنشأ قاعدة SQLite التجريبية في `.data/hr-local.sqlite` عند أول تشغيل. عند إعادة التشغيل يبقى العمل محفوظًا، وتحتاج إلى اختيار حساب التجربة مجددًا لأن الجلسات مؤقتة.

يمكن نسخ `.env.example` إلى `.env` لتعديل المنفذ. التزامات البيئة موثقة في [قرار التقنية](docs/decisions/001-local-foundation.md).

## الصفحات ورحلة التجربة

- لوحة العمل: ملخص الطلبات والرصيد وتقويم أسبوعي.
- الملف الوظيفي: بيانات العمل وسجل الإجازات.
- دليل الفريق: بحث وتصفية بحسب القسم، ضمن نطاق صلاحية المستخدم.
- الإجازات: إنشاء طلب ومراجعة احتساب أيامه ومتابعته وسحب المعلّق.
- الموافقات: مراجعة مدير ثم موارد بشرية، مع سبب رفض عند الرفض.
- تقويم الفريق: إجازات معتمدة، وتنقل بين الأشهر وتفاصيل اليوم.

لتجربة الرحلة كاملة: اختر **سارة القحطاني**، وقدّم إجازة في فترة لا تتداخل مع طلبها الحالي. بدّل إلى **عمر الشمري** من أسفل القائمة ووافق من صندوق الموافقات. بدّل إلى **نورة العتيبي** للاعتماد النهائي. عد إلى حساب سارة لرؤية الحالة والرصيد. جميع الأسماء والعلاقات والأرصدة مختلقة للتجربة.

لا يمكن لنورة أو عمر تقديم طلب شخصي حاليًا: لا يوجد مسار مستقل مكتمل لهما في عينة الأدوار. يعرض النظام السبب بدل ترك الطلب عالقًا أو السماح باعتماد ذاتي.

العناوين تستخدم خط **The Year of Handicrafts** الذي قدمه المستخدم، بملفات WOFF2 محلية ومدات انتقائية. نصوص النماذج والجداول تستخدم **IBM Plex Sans Arabic** محليًا. لا تعتمد الواجهة على خدمات خطوط أو صور خارجية.

## الفحوص

```sh
npm run typecheck
npm test
npm run build
npx playwright install chromium webkit
npm run test:e2e
```

اختبارات المتصفح تشغّل نسخة مبنية منفصلة على 4318 بقاعدة في الذاكرة. لا تغيّر قاعدة العرض المحلية. تتضمن رحلة الطلب والصلاحيات والجوال وفحوص axe الآلية على Chromium وWebKit. النتائج الفعلية وحدود الفحص في [STATE.md](STATE.md).

لفحص رابط المعاينة المأذون به نفسه: `HR_TEST_HOSTED=true npm run test:e2e`. هذا الخيار يستهدف نطاق Railway المثبت فقط وينشئ تجارب وهمية مستقلة؛ لا يقبل رابط إنتاج آخر.

لتشغيل النسخة المبنية محليًا بعد `npm run build`:

```sh
npm run preview
```

هذا الأمر يسمح صراحة بوضع المعاينة الاصطناعية، ويبقى الاستماع على `127.0.0.1` فقط. ليس إعداد نشر إنتاج.

## معاينة Railway

الرابط المخصص: https://hr-production-90b34ef5.up.railway.app . حالة التحقق الفعلية في [STATE.md](STATE.md).

تضبط إعدادات الخدمة في Railway بناء الواجهة بـ`npm run build` ثم تشغيل Express عبر `HR_MODE=hosted-demo HR_PUBLIC_ORIGIN=https://hr-production-90b34ef5.up.railway.app npm start` وفحص `/api/health`. نسخة توثيقية من القيم في `docs/railway-preview-settings.json`؛ ليست ملف إعداد يُطبّق تلقائيًا. لوحة Railway أظهرت أن Config as Code القديم لا يقبل خدمات جديدة، لذلك ثبتنا القيم مباشرة في الخدمة وفعّلنا النشر التلقائي من `main`. يستخدم التطبيق منفذ `PORT` ويستمع على `0.0.0.0` في هذا الوضع فقط.

لكل زائر بيانات وهمية مستقلة؛ تبديل حساب التجربة يحافظ على مساحة الزائر نفسها. التغييرات مؤقتة: تزول بعد ساعتين من الخمول، أو ثماني ساعات من بدء التجربة، أو عند إعادة نشر الخدمة. لا تستخدم بيانات حقيقية. الحد 50 مساحة نشطة وعملية خادم واحدة، بلا قاعدة خارجية أو Volume. تفاصيل العزل والتراجع في [قرار المعاينة](docs/decisions/002-hosted-synthetic-preview.md).

## حفظ البيانات والترحيل والتراجع

الترحيلات المرقمة في `server/migrations/` تطبق ذريًا وتوثق في `schema_migrations`. لا يعاد استبدال سجل الرصيد أو التدقيق. التفاصيل في [دليل الخادم](server/README.md).

```sh
npm run db:backup
npm run db:verify -- .data/backups/اسم-النسخة.sqlite
```

يستخدم النسخ واجهة SQLite للنسخ المتسق حتى عند تشغيل التطبيق، ثم يختبر نسخة مستعادة في موقع مؤقت ويقارن جميع سجلات جداول التطبيق ببصمة محتوى دون طباعة البيانات الشخصية. النسخ محلية غير مشفرة في هذه التجربة، ومجلد `.data` مستبعد من Git؛ هذا لا يحقق متطلبات النسخ الإنتاجي.

للتراجع: أوقف الخادم، انقل مجلد `.data` الحالي كاملًا إلى موقع محفوظ، أنشئ `.data` من جديد، وانسخ قاعدة النسخة المتحققة إلى `.data/hr-local.sqlite` ثم شغّل النسخة البرمجية المتوافقة. لا تنسخ فوق قاعدة نشطة ولا تُبقِ ملفات WAL قديمة بجوار قاعدة مستعادة. لا يوجد ترحيل هابط يحذف السجل التاريخي.

## الحدود الحالية

الجلسات والأدوار تجريبية، والسياسة ذات 24 يومًا وجدول الأحد–الخميس **سياسة اصطناعية وليست لائحة سبق أو قاعدة نظامية**. تمنع API الوصول العابر للموظفين والاعتماد الذاتي وتكرار الحجز والكتابة على نسخة قديمة. تُخفى ملاحظات طلبات الفريق عن المدير.

لم تنفذ: الدخول المؤسسي وMFA، إدارة موظفين/عقود قابلة للتحرير، رفع مستندات، أرصدة افتتاحية حقيقية، تفويض واعتماد بديل، إلغاء إجازة معتمدة وعودة مبكرة، الاستيراد، الرواتب، خدمات الرسائل أو التكاملات الحكومية. لا بيانات حقيقية؛ الشيفرة مرفوعة إلى GitHub ومعاينة Railway الاصطناعية مأذون بها من المستخدم.

المستودع المستهدف الذي حدده المستخدم: https://github.com/sabq4org/HR . راجع STATE.md لمعرفة حالة الربط/الرفع الفعلية.
